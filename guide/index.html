Claude Certified Architect – Foundations (CCAR-F)

Field Guide

Built backwards from a passing sitting at 892/1000 (cut 720). Every item is single-answer, four options, one correct — no multi-select. Distractors are closely spaced: the plausible prompt-level or over-engineered alternative to the correct structural mechanism. This guide tells you which mechanisms actually get tested, where confident preparation still leaves you exposed, and the one mental habit that answers most items.

The one rule that answers 70% of items

Deterministic beats probabilistic. When torn between two options, ask: which one makes the failure impossible rather than less likely? Hooks and gates beat prompt instructions. Schemas beat "please return valid JSON." Pinned fact blocks beat better summarization. The plausible-but-softer option is the distractor's home address.

Weighting

Five domains, sixty items

D1 + D3 + D4 are two-thirds of the exam. D5's nine items concentrate on a few heavily-tested judgements (escalation triggers, provenance, lost-in-the-middle), so each one is cheap to secure.

D1 · Agentic Architecture & Orchestration

27% · ~16 items

The heaviest domain. Most items reduce to one question: where does control live — in the model's prose, or in the structure around it? The agent is the loop, not the model. Hub-and-spoke is the only tested topology.

stop_reason · subagent isolation · hooks · decomposition · sessions

D2 · Tool Design & MCP Integration

18% · ~11 items

Tool descriptions are the model's only source of constraint signals. Structured error codes enable targeted recovery. Removing a tool from the registry is the only deterministic prevention. MCP scope follows task need.

tool descriptions · error signals · tool scoping · MCP scope · built-in tools

D3 · Claude Code Configuration & Workflows

20% · ~12 items

Project-level CLAUDE.md travels with the repo. Path-scoped rules apply conventions by file pattern. Plan mode is for architectural decisions before execution. CI isolation comes from fresh containers, not branch comparison.

config scope · commands/skills · path rules · plan mode · iterative refinement · CI/CD

D4 · Prompt Engineering & Structured Output

20% · ~12 items

Replace vague qualifiers with explicit categorical criteria. Few-shot examples beat more rules. Nullable fields prevent fabrication. Batch API for latency-tolerant jobs, sync for interactive gates. Independent review beats self-review.

explicit criteria · few-shot · schema design · retry/validation · batch vs sync · review independence

D5 · Context Management & Reliability

15% · ~9 items

Structured facts survive summarization; prose decays. Ask clarifying questions rather than guessing. Errors propagate as errors, never empty-success. Search before asking. Aggregate figures hide weak segments.

structured facts · escalation · error propagation · codebase exploration · stratified analysis · provenance

Deterministic beats probabilistic — everywhere

This single principle connects most items across all five domains. The exam consistently tests whether you can distinguish structural enforcement from prompt-level suggestion.

The distractor's home address

The plausible-but-softer option is almost always the wrong answer. More prompt examples, lower temperature, "be more critical" instructions, and self-review are all probabilistic controls that can be talked past. If the scenario involves money, ordering, compliance, or safety — the answer is structural.

Where preparation fails

Seven gaps from a real sitting

These seven objectives scored below 100% on the exam behind this guide. In each case, the cause was the same: recognition outran understanding — the correct answer was picked by pattern match, not by deriving the mechanism.

Gap 1 · Multi-phase workflow as a third option (0%)

Training that only ever contrasts plan mode with direct execution leaves "multi-phase workflow" as an unlabeled middle zone. The exam tests all three. A multi-phase workflow is a sequence of discrete phases (explore → plan → implement → review), each with its own checkpoint or approval gate, versus plan mode's single plan-then-execute cycle.

Gap 2 · Prefilled responses as structured output (0%)

The structured-output strictness spectrum has three rungs: prompt-only formatting (weakest), prefilled assistant turn with opening brace (constrains continuation), and tool use + JSON schema + forced tool_choice (strictest). Prefilling was never covered by any session bank. Match the rung to the consumer's fragility.

Gap 3 · MCP scope selection and discovery verification (50%)

Three decisions arrive as one: where the server definition lives, where the secret lives, and how you confirm the tools are actually there. Shared server → project scope. Personal secret → environment expansion, never committed. Missing tools → verify discovery before debugging the server.

Gap 4 · Inclusion and exclusion criteria (50%)

A prompt that says what to find, with options that only strengthen the positive instruction. The flood comes from the missing negative boundary. Exclusion criteria name the categories not to report — they are how you stop the model doing work it shouldn't.

Gap 5 · Glob vs Grep for call-site enumeration (60%)

Glob matches file paths/names. Grep searches file contents. A rename or signature-change task needs Grep on the function name to enumerate call sites, then Read on each match. Glob alone cannot answer "who calls this." Run it once by hand — the distinction sticks the first time, not the tenth time you read it.

Gap 6 · CLI startup performance: --bare (100% objective, missed sub-flag)

A 100% objective-level score does not guarantee sub-flag coverage. --bare skips skill/command/settings auto-discovery for faster scripted calls. --system-prompt-file injects required prompt content directly. When the script already knows the content, --bare skips discovery and the file flag supplies the text.

Gap 7 · Recognition vs. mechanism understanding

The MCP resources-vs-tools objective scored 100%, but the correct answer was chosen by pattern match, not derived from the mechanism. The actual reason resources are faster: each tool call costs a full model reasoning round-trip; a resource is read directly by the client with no model turn required. Removing exploratory tool calls removes turns, and the turns are the latency.

The calibration signal

A correct multiple-choice answer is not proof of mechanism understanding. After each item, ask: could I explain why this answer is correct to someone who picked the wrong one? If the answer is "it just seemed right," that's recognition, not mechanism. The gap between "concept drill feels easy" and "mock feels hard" is real signal — it means you recognize mechanisms but cannot yet select them under scenario pressure.

The traps

Fourteen judgement patterns

Each trap is the shape of a question rather than a fact: how it presents, a worked example, and the discrimination that resolves it. Read the trap, cover the resolution, work the example, then check yourself.

Seed patterns

1. stop_reason timing — the model sounds finished

The model's text sounds finished, and an option treats that as the stop signal — or a loop condition keys on the wrong stop_reason.

Resolution: text and tool_use blocks coexist in one response; prose is never a completion signal. The loop's contract is stop_reason. Branch on it: tool_use → execute, end_turn → stop.

2. Config-scope inverse framing — "works on my machine"

The scenario is stated backwards — "works on my machine, teammate doesn't have it" — and the options make you convert between scopes under pressure.

Resolution: Team standards belong at project scope because that is the tier version control distributes. User scope is personal by design — it never travels with the repo. Whoever must have the rule determines the tier.

3. Tool-scoping vs topology attribution — who's at fault?

An agent misuses a tool, and the options split between "change the tool surface" and "change the agent structure." The scenario's numbers tell you which.

Resolution: Selection accuracy degrades as tool count grows. A general-purpose tool inside a specialized agent is scope creep — the fix is a scoped tool surface. If the misuse is available to happen, scope it out before you supervise it.

4. Aggregate-vs-stratified review — the impressive metric

An impressive aggregate metric, and options that accept it. The correct answer attacks the measurement.

Resolution: 96% overall can be 99% on typed forms and 78% on handwritten ones. Stratify by document type and field before deciding. Self-reported confidence is uncalibrated — a routing key, not truth.

5. Schema-honesty — nullable fields prevent fabrication

A required field the source sometimes lacks. The model does not fail loudly — it fabricates a plausible value to satisfy the schema.

Resolution: A required non-nullable field forces the model to choose between fabricating and failing schema validation. Nullable fields plus an explicit null-when-unstated rule give the model an honest exit.

6. Batch-vs-sync split — the ~50% discount trap

The ~50% discount tempts a "batch everything" answer; the decider is whether anything blocks on the result.

Resolution: Batches trade latency for cost: up to a 24-hour window and no SLA. The more a caller blocks on the result, the less suitable the batch window. "Typically finishes in about two hours" is not a guarantee.

7. Context preservation under pressure — facts decay

Precise facts decay across a long conversation, and options offer better compression. Compression is the cause, not the cure.

Resolution: Summarization is precisely what rounds "$1,204.60" into "about $1,200 from mid-March." Facts that must survive are pinned verbatim, every turn, outside whatever gets summarized. A bigger window postpones the decay; it does not prevent it.

Post-exam gap patterns

8. The three-way workflow decision — plan mode, direct, or multi-phase?

The options offer three patterns and the scenario quietly demands the third. Training that only contrasted plan mode with direct execution leaves "multi-phase workflow" as an unlabeled middle zone.

Resolution: Plan mode is a single plan→approve→execute cycle. Multi-phase is a sequence of discrete phases, each gating the next. The selection criteria are task scope, risk level, and human-approval requirements — read the scenario for where the approvals live.

9. Choosing the structured-output rung — match strictness to consumer

"The output must be JSON" with options spanning the whole strictness spectrum. Picking too weak breaks the pipeline; picking the strongest "to be safe" can be the over-engineered distractor.

Resolution: Prefilling with { constrains continuation without tool machinery. Tool use + schema + forced tool_choice is the strictest rung. Match the rung to the consumer's fragility — a human reader needs less than a strict parser.

10. MCP scope, secrets, and discovery — three decisions as one

Where the server definition lives, where the secret lives, and how you confirm the tools are actually there — usually drilled separately, arriving as one scenario.

Resolution: Shared server → project scope. Personal secret → environment expansion, never committed. Missing tools → verify discovery (what the client listed at connection time) before debugging the server.

11. Inclusion and exclusion criteria — the missing negative boundary

A prompt that says what to find, with options that only strengthen the positive instruction. The flood comes from the missing negative boundary.

Resolution: A model told what to find but not what to skip will generate findings in categories where its performance is unreliable. Exclusion criteria name the categories not to report — they are how you stop the model doing work it shouldn't.

12. Glob finds paths, Grep finds callers — the most confused tool pair

A change-propagation scenario with a Glob option that sounds thorough. Glob can enumerate every file that might matter and still answer none of "who calls this."

Resolution: Call sites are content, and Glob matches only paths. Grep to enumerate, Read to verify, then Edit. Run it once by hand in a real repo — the distinction sticks the first time you run it.

13. Fast scripted startup — --bare earns its keep

A scripted invocation is slow, and the options offer bigger machines or caching. The cost is auto-discovery — and you skip it only because you're supplying the prompt content yourself.

Resolution: --bare skips skill/command/settings auto-discovery. --system-prompt-file injects the content directly. When the script already knows the content, --bare skips discovery and the file flag supplies the text.

14. Why resources are faster — the round-trip mechanism

"Expose it as a resource" is easy to recognize and easy to choose for the wrong reason ("resources are cached"). The actual mechanism is about model turns.

Resolution: Every tool call is a model reasoning round-trip. A resource read happens client-side with no model turn at all. Removing exploratory tool calls removes turns, and the turns are the latency. A correct option chosen without the mechanism is luck that doesn't repeat.

The gap is the signal
